# Link Shortener — сервис сокращения ссылок

Учебный Key Project по ТЗ PROMO IT. Консольное Java-приложение позволяет создавать короткие ссылки, открывать исходный URL в браузере, задавать лимит переходов и управлять своими ссылками. Ссылки удаляются по истечении TTL. UUID создаётся при первом успешном сокращении и используется как идентификатор владельца.

## Требования и запуск

- JDK 17 или новее (`java -version`, `javac -version`), внешние библиотеки не нужны.
- Для реального открытия ссылок — графическая среда и браузер по умолчанию.
- Запускать команды из корня проекта, где находится `config.properties`.

### Windows (PowerShell)

```powershell
chcp 65001
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
java -jar out/link-shortener.jar
```

### Linux / macOS / Git Bash

```bash
bash scripts/build.sh
java -jar out/link-shortener.jar
```

Сборочный скрипт компилирует основной код и тесты, запускает тесты и создаёт JAR. Можно указать другой конфигурационный файл: `java -jar out/link-shortener.jar test.properties`.

### IntelliJ IDEA

1. Open → выберите папку проекта. В Project Structure установите SDK 17 или новее и language level 17.
2. Пометьте `src/main/java` как Sources Root, а `src/test/java` — как Test Sources Root (правой кнопкой, Mark Directory as).
3. Откройте `src/main/java/shortener/Main.java`, нажмите Run возле `main`. Working directory — корень проекта. При необходимости добавьте VM option `-Dfile.encoding=UTF-8`.
4. Для тестов можно запустить `main` класса `shortener.TestRunner` с classpath модуля тестов или использовать скрипт сборки в терминале IDE.

## Команды

| Команда | Назначение |
| --- | --- |
| `help` | Помощь и примеры |
| `create https://example.org/a 2` | Создать ссылку с лимитом 2; без лимита берётся значение по умолчанию |
| `open КОД` | Открыть исходный URL; можно ввести полный короткий адрес вместо кода |
| `https://short.local/КОД` | То же без команды `open` |
| `list` | Список своих ссылок: URL, счётчик, статус, срок действия (UTC) |
| `whoami` | Текущий UUID |
| `new` / `logout` | Выйти из текущей сессии; следующая команда create создаст нового пользователя |
| `login UUID` | Вернуться к сохранённым ссылкам |
| `edit-limit КОД 5` | Изменить общий лимит без сброса счётчика |
| `edit-url КОД https://example.com` | Изменить исходный URL, сохранив лимит и TTL |
| `delete КОД` | Удалить собственную ссылку |
| `notifications` | Показать непрочитанные уведомления (обычно выводятся автоматически) |
| `exit` | Завершить работу |

В командах вместо `КОД` и `UUID` подставляйте реальные значения, выданные программой. `short.local` — условный префикс для CLI, не публичный домен и не HTTP-сервер: короткую ссылку нужно ввести в консоль приложения, а не в адресную строку браузера. Открывать ссылку может любой пользователь без UUID, редактировать и удалять — только её владелец.

## Конфигурация

| Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `ttl.seconds` | 86400 | Время жизни новой ссылки в секундах |
| `limit.default` | 10 | Лимит, если не указан пользователем |
| `limit.max` | 1000000 | Верхняя граница лимита |
| `short.prefix` | `https://short.local/` | Префикс короткой ссылки |
| `code.length` | 7 | Длина генерируемого кода (4–32) |
| `cleanup.millis` | 1000 | Интервал фоновой очистки, мс |
| `data.file` | `data/state.properties` | Локальный файл данных, относительно конфигурации |

Изменение TTL применяется к новым ссылкам, уже созданные имеют собственное время истечения. Изменение префикса изменит представление коротких адресов (старые коды останутся действительными). Не меняйте префикс при эксплуатации. Конфигурация читается при старте. Данные сохраняются автоматически; не публикуйте `data/` и UUID, поскольку знание UUID даёт доступ к управлению ссылками. Локальный файл данных не зашифрован. Один файл данных обслуживается одним процессом; параллельная работа разных пользователей имитируется сменой сессии внутри CLI.

## Архитектура и решения

```text
src/main/java/shortener/
  Main.java                  сборка зависимостей, планировщик и блокировка файла
  core/
    Link.java                неизменяемая модель ссылки
    State.java               снимок состояния и уведомления
    LinkService.java         бизнес-логика, права, лимит, TTL
    Settings.java            проверенные параметры сервиса
    Urls.java                валидация HTTP(S) URL
    Store.java               контракт хранилища
    Browser.java             контракт открытия браузера
  infra/
    Config.java              чтение properties
    FileStore.java           запись/чтение снимка состояния
    CodeGenerator.java       случайный Base62-код
    DesktopBrowser.java      адаптер Desktop API
  ui/
    Console.java             разбор команд, сообщения, текущий UUID
src/test/java/shortener/
  TestRunner.java            unit и интеграционные тесты
```

- Core не зависит от CLI или конкретного хранилища. Внедрение `Store`, `Browser`, `Clock` и генератора через конструктор позволяет тестировать правила без GUI и реального времени.
- Генератор выдаёт случайный Base62-код, сервис проверяет его по множеству всех когда-либо выданных кодов. Коллизия приводит к повторной генерации; код не используется повторно даже после удаления. При 1000 неудачных попытках операция завершается ошибкой вместо выдачи дубликата.
- TTL задаётся системой. При `now >= expiresAt` ссылка удаляется, её владелец получает уведомление. Фоновый планировщик выполняет очистку, когда CLI ждёт ввод. Проверка срока также происходит перед операциями и при запуске после простоя.
- Последний разрешённый переход выполняется, после него ссылка блокируется. В подробном ТЗ требуется блокировка при лимите и удаление по TTL; поэтому заблокированная ссылка остаётся до удаления владельцем или по TTL, а владелец может увеличить лимит. Это осознанный выбор в пользу подробного ТЗ и критерия редактирования лимита.
- Синхронизация методов предотвращает обход лимита конкурентными запросами. Переход резервируется на диске перед вызовом Desktop API; при исключении браузера выполняется откат. Успех означает передачу запроса браузеру, а не подтверждённую загрузку страницы. При аварийном завершении между резервированием и открытием счётчик может увеличиться без перехода — безопаснее, чем обход лимита.
- UUID генерируется при первом успешном create. Все операции изменения проверяют владельца; редактирование URL или лимита не продлевает TTL. Лимит нельзя установить ниже уже совершённых переходов.
- Уведомления адресованы владельцу, сохраняются до доставки и автоматически выводятся в его активной сессии. При истечении TTL или лимита предлагается создать новую ссылку.
- `FileStore` сохраняет состояние атомарной заменой файла; для работы требуется файловая система с поддержкой атомарного перемещения. Данные, UUID и выданные коды сохраняются между запусками. Это локальное учебное хранилище, не серверная БД.

## Тестирование

Запустите `bash scripts/build.sh` или `scripts/build.ps1` из PowerShell. Самостоятельный тестовый runner не требует JUnit или других библиотек; каждая проверка сообщает PASS/FAIL, любое падение приводит к ненулевому коду выхода. 19 unit и 4 интеграционных сценария:

- URL, настройки, генерация и обработка коллизий, уникальность для разных владельцев;
- создание UUID, несколько ссылок одного владельца, права на редактирование и удаление;
- лимиты, граничные значения, отказ браузера/хранилища, повторная активация;
- TTL на точной границе, уведомления и их изоляция;
- файловое сохранение/перезапуск, сквозной CLI с подменой браузера, фоновая очистка, конкурентные запросы.

### Ручная проверка в графической среде

1. Запустите CLI, введите `create https://example.org 2`, сохраните UUID A и код A. Введите `list`.
2. Введите `new`, затем `create https://example.org 2`. UUID B и код B должны отличаться от A.
3. От имени B попробуйте `edit-limit КОД_A 3`, `edit-url КОД_A https://example.com` и `delete КОД_A`: все операции должны быть отклонены.
4. Введите `login UUID_A`, затем дважды `open КОД_A`: должен открываться браузер. Третья попытка блокируется, после второй появляется уведомление. Увеличьте лимит до 3 и убедитесь, что доступ восстановился.
5. Для быстрой проверки TTL скопируйте `config.properties` в `test.properties`, задайте `ttl.seconds=10`, `data.file=data/test-state.properties`. Запустите приложение с аргументом `test.properties`, создайте ссылку и подождите 11–12 секунд. Уведомление должно появиться без ввода команды. `list` должен быть пуст, открытие — отклонено.
6. Перезапустите приложение с исходной конфигурацией, выполните `login UUID_A` и проверьте сохранение ссылок и счётчиков.

Автоматические тесты используют подмену браузера, а не реальное окно браузера. Реальный Desktop API нужно проверить локально по шагу 4.

## Автоматизация

`.github/workflows/ci.yml` запускает CI при push и pull request на JDK 17: сборка, тесты, JAR, строгая проверка компилятора `-Xlint:all -Werror`. `.editorconfig` задаёт единый стиль отступов и кодировку.

## Публикация

Создайте пустой репозиторий GitHub `link-shortener` и из папки проекта выполните:

```bash
git init
git add .
git commit -m "Implement link shortener service"
git branch -M main
git remote add origin https://github.com/YOUR_LOGIN/link-shortener.git
git push -u origin main
```

Замените YOUR_LOGIN на логин своего GitHub. Проверьте вкладку Actions и отправьте ссылку на репозиторий через форму сдачи проекта. Не добавляйте реальные UUID и файл данных в репозиторий.
